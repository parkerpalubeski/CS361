# Rewrite the following code using DI:
```
class Frotz:
    def __init__(self):
        self.left = Left()
        self.right = Right()

    # [a bunch of functions that use .left and .right]

f = Frotz()
```


Rewrite:
```
class Frotz:
    def __init__(self, left,right):
        self.left = left 
        self.right = right

f = Frotz(Left(), Right())
    
```
# Research: what are some issues with tightly coupled code?
* Tightly coupled code is more difficult to test
* Code is more difficult to modify if code is tightly coupled. In the first implementation of Frotz, you have to modify it to change the implementation of Left for instance.
* Tightly coupled code is more difficult to reuse
