# What is the difference between a GitHub fork and a regular repo clone?
A fork is a copy of a repository on GitHub itself, whereas a clone is a copy of a repo on your machine. Forks are the primary method for contributing to projects that aren't yours.
# Why is it a good practice to submit PRs on branches instead of putting them all on main?
This is best practice because main is supposed to be in a working state. So if your code breaks something, fixing it is a lot simpler. 
# Why should you sync with the upstream repo before you make a PR?
This prevents merge conflicts where the owner might have made changes while you were working. 
# What are the advantages and disadvantages of adding collaborators versus using PRs
Using collaborators significantly lowers the barrier to pushing code to the repo once added.. But you have to add them all individually, and they can push things that can break the code if they aren't careful. PRs allow you to review the code before merging.
