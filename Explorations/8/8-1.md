# Describe what a branch is and how it differs from a collection of related commits.
A branch is a separate commit that lets you isolate work and make changes safely without breaking the code in the main branch. None of its changes are applied to main until they are pushed to the main branch.

# Discuss why a git pull must, as part of its processing, perform a merge.
A git pull must perform a merge when your local branch (on your PC) diverges from the upstream branch on GitHub (or elsewhere). 

# What's the difference between a fast-forward merge and a normal merge? Under what circumstances can you perform a fast-forward merge?
A fast-forward is a merge that is done when there aren't any conflicts between the upstream branch and yours. In this case, your branch pointer simply goes to the main branch's commit. A normal merge on the other hand has to reconcile conflicts and even has to create a new commit just to create a place where changes are applied and disposed of.

# When you are switched to branch main, and you git merge somebranch, does that merge somebranch's changes into main? Or does it merge main's changes into somebranch?
It applies somebranch's changes into main. somebranch is the source branch.

# Can a merge conflict occur with a fast forward merge? Why or why not?
No, because a fast forward merge isn't done under circumstances where a merge conflict is possible. In a fast-forward, the source branch is a direct descendant of the destination.

# Outline the process you have to go through in Git to resolve a merge conflict.
1. Inspect the files that conflicted
2. Look at the conflicts within the file
3. Choose which version is correct
4. Add
5. Test
6. Commit
