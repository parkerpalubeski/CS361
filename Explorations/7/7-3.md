## Kanban limits the number of tasks in each column to control the work flow. How does Scrum control it?
Scrum controls it in fixed intervals. A developer is given a fixed number of tasks to complete in a fixed amount of time.
## Contrast Scrum's sprints with Kanban's continuous development. What are some of the benefits and drawbacks of each?
### Benefits
* Kanban allows for the most agile process possible. Developers can change priorities easily to address critical issues 
* Software can be released as soon as it meets the team's definition of done
* Less overhead from meetings and planning
### Drawbacks
* Kanban processes may lead to an obsession with performance metrics, e.g. tickets solved
* The lack of milestones/end-points may have a detrimental effect on motivation or sense of purpose for the developers
## What are some arguments for more granular columns on the Board? What are some arguments for fewer columns?
More granular columns allow teams to more easily see where work is getting stuck. For instance, if there aren't enough code reviewers, seeing a bunch of tasks piling up in the code review column will instantly tell you that there aren't enough people assigned to that role.
Fewer columns makes the board cleaner to look at, and gives a good idea of where everything is at. It also reduces the overhead of having to constantly update an item's status across 10 different categories.
